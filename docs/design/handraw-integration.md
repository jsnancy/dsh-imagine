# 设计方案：把 handraw-style 手绘提示词库集成进十六跟做图

> 目标：让「十六跟做图」在**不改变现有生图链路**的前提下，具备一个可浏览、可检索、可一键跟做的手绘风格模板库。
> 素材与提示词全部来自 [yang0/handraw-style](https://github.com/yang0/handraw-style)（v1.9.13，MIT License with Attribution Requirement）。
> 本文是**待评审的方案**，确认后再改代码。界面示意见同目录 `mock-library.png` / `mock-studio.png` / `mock-follow.png`（1440×960，真实素材渲染）。

---

## 0. 一句话结论

左侧栏新增第 2 个入口「模板库」，里面是 **594 条上游素材 + 60 个精选场景配方**（6 个域 × 10 个：知识科普 12 / 职场商业 10 / 生活方式 10 / 产品电商 10 / IP 品牌 8 / 漫画叙事 10）；卡片可以**点开看大图**、看完整提示词，点「跟做」填一句主题，Host 端**按上游规则确定性拼装**出一段完整提示词，直接填进现有创作页的输入框，并且可以**一键导出成 .md**——不改写、不调模型，生成按钮还是你现在那个。

---

## 1. 现状与约束（决定了方案能做什么）

| 现状 | 影响 |
| --- | --- |
| `lib/client.js` 是单文件 UMD（1473 行），UI 全部手写 React.createElement，无构建步骤 | 新增界面必须写进这个文件；不能引组件库 |
| 侧栏导航是**单页三节滚动**（`activeNav` 由滚动监听驱动，`gotoSection` 平滑滚动），不是路由 | 「模板库」必须是**视图切换**（`view = 'studio' | 'library'`），不能靠滚动到某节 |
| 生图链路：`POST /image-studio/api/generate` → `lib/codex.js` 打 ChatGPT 后端 `images/generations`，**请求体只有 `{prompt, size, background}`** | **不支持参考图/垫图**；模板的价值 = 给一段高质量 prompt，不是塞参考图 |
| `size` 只有 4 档：`auto / 1024x1024 / 1024x1536 / 1536x1024` | 模板推荐比例（3:4、4:5、9:16…）只能**映射**到像素档位，真实比例靠 prompt 里的「画幅比例：」约束 |
| 零 npm 依赖、自包含 npm 包（`files` 白名单） | 新增数据要打进包里；不能依赖用户本地有那个仓库 |
| 每个请求都过 `ctx.connection.requestRejection()` | 新增接口必须同样处理 |

上游资产体量（实测）：

| 资产 | 数量 | 体积 | 说明 |
| --- | --- | --- | --- |
| 全部素材图 | 594 张 webp + 若干总览图 | ≈ 40 MB | 画风 302×302 / 图型 ≈561×701 / 影调 512×512 |
| 提示词正文（styles.traits / layouts/*.md / colors.prompt / tones.desc） | 594 条 | 341 KB（gzip 91 KB） | 其中 170 条图型排版说明占 126 KB |
| 精选索引所需文本 | — | ≈ 90 KB（gzip 25 KB） | 编号、名称、分类、比例、字数等 |

**结论：提示词正文全部内置（341 KB，可 gzip），图片按需拉取 + 磁盘缓存，另内置一小批「封面集」保证首屏好看。**

## 2. 信息架构

```
十六跟做图
├── 生成图片（现有 01/02 节）
│   ├── 01 画面描述
│   │   ├── 【新增】模板参考横条（6 个槽位 + 「全部 →」）
│   │   ├── 【新增】已套用模板条（缩略图 + 参数摘要 + 重新拼装 / 导出 .md / 移除）
│   │   └── 提示词输入框（不变）+ 画布/背景 + 生成图片（不变）
│   └── 02 历史作品（不变）
├── 【新增】模板库
│   ├── 头部：仓库版本 + 素材缓存进度 + 「同步素材」
│   ├── 一级标签：精选场景 60 / 排版图型 170 / 画风 372 / 主题色·影调 52
│   ├── 二级筛选（chips，随一级变化）+ 搜索框
│   ├── 卡片网格（示例图 + 编号/版式角标 + 名称 + 参数或字数 + 跟做 / 看大图）
│   ├── 大图预览层（点卡片图或「看大图」→ 大图 + 完整提示词 + 参数 + 复制 / 导出 .md / 跟做）
│   └── 底部署名条
└── 账号与设置（现有）
```

两条主流程：

```
A. 从模板出发（逛）
模板库 → 挑卡片 →（[看大图] 先确认版式与画风 / [导出 .md] 直接存下来）
      → [跟做] → 填主题/可选画面要求 → 预览提示词 → [填充到创作页]
      → 回到生成图片：输入框已是完整提示词、画布已切到映射档、顶部出现已套用条 → [生成图片]

B. 从主题出发（写）
生成图片 → 写主题 → 在「模板参考」横条里点一张缩略图 → 该模板的画风/版式/配色套到**已写内容**上
        → 生成（此时是「我的主题 + 官方画风」的组合，A/B 两条路殊途同归）
```

要点：

- **精选场景是"配方"不是"素材"**：60 个，6 个域 × 10 个，清单见 [curated-60.md](curated-60.md)（每个都写清版式 / 画风 / 主色 / 影调 / 比例 / 模式 / 示例主题）。封面直接复用该版式的官方示例图，**不新增素材**。以后要加场景只改 `curated.json`，不动代码。
- 卡片信息分两种：**场景卡**显示「场景名 + 版式角标 + 参数行（`4:5 · 图文 · FA-021 · C-01`）」；**素材卡**显示「编号 · 名称 · 正文长度 · 建议比例」。
- 卡片右上角两个动作：`跟做`、`看大图`；鼠标移上去封面轻微放大 1.04，提示"可点"。
- 复用现有设计令牌与类名（`--isx-paper`、`.isx-sec-head`、`.isx-btn`…），新组件统一 `isx-tpl*` / `isx-lib*` 前缀，视觉与原面板同一套。
- 卡片统一 **4:5 竖图**（版式图 561×701 正好；画风是方图，居中留白）。
- 搜索匹配：场景名、编号（`SC-014` / `CT-23`）、中英文名、关键词（`留白`、`复盘`）、分类名、参考作者（`Mari Andrew`）。
- **一级标签「主题色·影调 52」是合并的**：颜色 36 + 影调 16，二级 chips 分「主题色 36 / 影调 16」，两者都不足以单独占一个一级位。

### 3.2 创作页（`mock-studio.png`）

01 区顶部插两块东西，其余原样不动：

1. **模板参考横条**：6 个槽位（106×72），前 5 个是"最近用过 / 本站推荐"，最后一个虚线 `+` 打开模板库；点任意缩略图 = 把它的画风/版式/配色套到当前输入框内容上。
2. **已套用模板条**：左侧 3px 高亮边 + 32×23 缩略图 + 模板名 + 参数摘要（`SC-014 · FA-021 · C-01 · T-04 · 3:4 · 图文一体`）+ `重新拼装`、`导出 .md`、`移除`。用户随后手改提示词也不影响这条显示（它只是记录，不锁定内容）。

> 关键设计：**拼装结果就是普通文本**，落在原来的 textarea 里。用户随时可以删改，也可以在编辑后直接点生成——没有"锁定模式"，没有新的生成入口。

### 3.5 一键导出提示词（`.md`）

三个入口，都走同一个导出器：

| 入口 | 导出内容 |
| --- | --- |
| 大图预览层「导出 .md」 | 该条**原始**提示词（未套主题） |
| 跟做对话框「导出 .md」 | **拼装后**的完整提示词（含用户主题与所选参数） |
| 创作页「已套用」条「导出 .md」 | 同上，等价于导出当前输入框里的东西 |

文件形如 `handraw-IG-032-手绘编辑式知识信息图.md`，内容：

```markdown

version: 1.9.13
license: MIT License with Attribution Requirement

params: { layout: IG-032, style: FH-002, color: C-04, tone: T-01, ratio: "4:5", mode: graphic-text }
exported: 2026-11-27

<!-- 素材与提示词来自 yang0/handraw-style（v1.9.13）
     https://github.com/yang0/handraw-style

```

- 下载走浏览器 `Blob + a[download]`，**不需要新接口、离线可用**；文件里的 front matter 让"用这段提示词生成的图"以后还能溯源到具体模板。
- front matter 里固定带 `source / version / license`，正文末尾再带一行署名注释——导出物本身就是署名要求的一部分。
- P1 加"导出到 `$DSH_HOME/image-studio/exports/` 并 reveal"，以及**批量导出**：当前筛选结果 / 整个精选场景集合导成一个 .md 或 .zip。

## 4. 一键跟做：拼装器规则

**位置**：Host 端 `lib/handraw/compose.js`（纯函数，便于单测），由 `POST /templates/compose` 暴露。
**原则**：只做**模板填充**，不改写、不润色、不调模型——保证"跟做的结果和库里的风格一致"。

拼接顺序与块（移植自上游 `plugins/dsh-handraw-style/prompt.js` 的 `compilePrompt`）：

| # | 块 | 来源 | 何时出现 |
| --- | --- | --- | --- |
| 1 | `画风：<generation_name>（<number>）` / `参考风格名称：<reference>` / `纯视觉画风特征（禁止照抄示例主体）：<traits>` | styles.json | 选了画风 |
| 2 | 融合原则（两个画风同时选时） | 上游固定文案 | P2「风格融合」才用 |
| 3 | `<prompt_zh>`（原文自带「主题色：」前缀，不重复加） | colors.json | 选了主题色 |
| 4 | `主题：<用户填的主题>` | 用户输入 | 必填；空则用占位文案 |
| 5 | 业务场景 / 受众 | 用户可选填（P1） | 电商/信息图更适用 |
| 6 | `画幅比例：<ratio>` | 模板默认或用户改 | 总是 |
| 7 | `影调：<name_zh>。<desc_zh>` | tones.json | 选了影调 |
| 8 | `【大量留白】/【中等留白】/【少量留白】` | 用户选 | 选了留白 |
| 9 | `排版图型（<id>）：<prompt>` | layouts/<id>.md | 选了图型 |
| 10 | 重绘指令（垫图重绘场景） | — | P2 |
| 11 | 模式后缀：图文一体 → `文字参与构图，图文一体`；纯图 → `画面内不生成额外标题、标识或可读文字。`；电商 EC-* → 电商实拍约束 | 上游固定文案 | 总是 |

返回 `{ prompt, promptZh, promptEn, mode, ratio, words, blocks[], warnings[] }`，附带每块来源，前端用来做参数摘要与预览。`warnings` 用于「该模板不适用当前画布」这类提示。

**比例映射**（决策点 D）：

| 模板建议比例 | 提交给生图的 size |
| --- | --- |
| 1:1 | `1024x1024` |
| 3:4 / 4:5 / 9:16 / 2:3 / 3:2 竖 | `1024x1536` |
| 4:3 / 16:9 / 21:9 / 2.35:1 横 | `1536x1024` |

真实比例写进 prompt（`画幅比例：3:4`），像素档位只是模型侧的近似。UI 上把画布下拉扩成 9 个比例项，括号里标像素（如「3:4（1024×1536）」），并在旁边保留原来那句「模型可能按画面内容微调尺寸」。

```
lib/data/curated.json        60 个精选场景配方（6 域 × 10，layout+style+color+tone+ratio+mode+示例主题）≈ 14 KB
lib/data/img/…               封面集：60 个场景用到的版式示例图（去重后 ≈ 56 张）≈ 5.5 MB
scripts/build-catalog.mjs    从上游 checkout 生成上面两个 json + 拷贝封面集，并校验 curated 里每个 ID 都存在
```

`catalog.json` 在 Host 侧 gzip 后约 91 KB，一次请求 + ETag 缓存；前端只在第一次进模板库时拉取，之后复用内存。

### 5.2 图片三级来源

| 优先级 | 来源 | 触发 |
| --- | --- | --- |
| 1 | `$DSH_HOME/image-studio/templates/<path>` 本地缓存 | 命中即用（`cache-control: immutable`） |
| 2 | 包内 `lib/data/img/` 封面集 | 精选场景的首屏 |
| 3 | CDN 按需拉取：`cdn.jsdelivr.net/gh/yang0/handraw-style@<version>/images/<path>` → 失败回退 `raw.githubusercontent.com` | 其余卡片进可视区域时 |

- 图片走 Host 代理（`GET /image-studio/templates/asset/<path>`），前端只认同源 URL，**避免跨域与 CSP 问题**；Host 只在白名单路径内转发，越权直接 400。
- 拉下来的图写入本地缓存，第二次不再联网。
- **「同步素材」**按钮：后台把当前分类（或全部 594 张）拉完，头部显示 `已缓存 128/594` 进度，可中断。
- 可选（P1）：设置里加一个「本地仓库目录」——已经 clone 过 handraw-style 的人直接指目录，零下载。

不做的事：不把 40 MB 全量塞进 npm 包（安装体验会崩），也不默认全量下载。

### 5.3 Host 接口契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/templates/index` | 返回 `{version, counts, groups, items[]}`；gzip + ETag；`items` 只含展示字段，`prompt` 正文在 `/templates/item/<id>` 取 |
| GET | `/templates/item/<id>` | 单条完整数据（含 prompt 正文），用于详情弹层与跟做预览 |
| POST | `/templates/compose` | body：`{layout?,style?,color?,tone?,ratio?,mode?,theme,brief?,whitespace?}` → 拼装结果 |
| GET | `/templates/asset/<path>` | 图片代理 + 磁盘缓存，路径白名单 |
| POST | `/templates/sync` | `{scope:'curated'|'category'|'all', key?}` 后台同步；返回 job id |
| GET | `/templates/sync` | 进度 `{cached, total, running}` |

全部沿用现有约定：`connectionRejection()` 前置、`sameOrigin` 校验、`readJsonBody` 32K 上限、`ctx.effect` 注册。

## 15.1 落地方式

皮肤没有改写面板结构，而是新增一份独立样式表，由 Host 提供、面板注入：

| 位置 | 作用 |
| --- | --- |
| `lib/skin-handdrawn.css` | 皮肤本体，约 1300 行。浅色定义全部 `--hd-*` / `--isx-*` 变量与结构性规则；文件末尾用 `[data-scheme='dark']` 一套变量接管深色 |
| `lib/index.js` 的 `SKIN_FILE` + `serveSkin()` | `GET /image-studio/skin.css`（`text/css`，私有缓存 1 小时） |
| `lib/client.js` 的 `SKIN_ID` 注入块 | 面板启动时插 `<link rel="stylesheet" href="${API}/skin.css?v=0.5.0">`，并把它标记为 `data-plugin-css="dsh-imagine/skin.css"` 以去重 |

选独立文件而不是塞进 `client.js` 的 `<style>`：皮肤只改观感、不参与逻辑，独立文件便于单独迭代、可被浏览器缓存，也方便将来做「手绘 / 朴素」开关。**回退方式**：删掉 `lib/client.js` 中的 `SKIN_ID` 注入块即可回到原界面。

## 15.2 浅色：一张纸

- 纸：`#fbf6ea` 底 + feTurbulence 纸纹 + 径向暗角；
- 线：炭笔 `#2e2823`、不规则圆角（`12px 5px 14px 6px / 6px 14px 5px 12px`）、硬阴影 `2px 2px 0`；
- 色：朱砂 `#cf4a32` 强调 + 马克笔黄 `#ffd966` 选中高亮；
- 版面语言：额度四格 → 四张不同色调的便签（米/粉/蓝/绿，各一条朱红短横线）；模板卡 → 带胶带的贴纸（`nth-child(4n)` 交替 0.35–0.9° 旋转，悬停回正）；提示词框 → 方格纸；分节号 01 → 手绘椭圆圈；标题 → 波浪下划线 + 一颗手绘小星；下拉 → 手绘小三角。

## 15.3 深色：深咖啡纸与粉笔

同一套结构规则，只换变量与四个 SVG 资源：

| 变量 | 浅色 | 深色 |
| --- | --- | --- |
| `--isx-paper` | `#fbf6ea` | `#221c16` |
| `--isx-ink` | `#2e2823` | `#f3ebdc` |
| `--isx-accent` | `#cf4a32` | `#e8694f` |
| `--hd-surface`（卡片/输入） | `#fffdf7` | `#2b241c` |
| `--hd-tape-bg` | 半透明米黄 | 半透明暗金 |
| `--hd-veil`（弹层页眉/页脚蒙层） | 米白 82% | 深咖啡 82% |

深色下另外三处必须单独处理（都已实现）：

1. **SVG 不吃 CSS 变量**：噪点层的 `opacity` 曾写成 `var(--hd-noise-opacity)`，导致属性失效、弹层变成满屏颗粒；改为硬编码并在深色块里重写整层 `background-image`。
2. **手绘描边色**：波浪线/星星/铅笔/圈是 SVG data URI，深色下逐条重绘为 `#ea6c52`；下拉小三角重绘为粉笔白。
3. **半透明白**：`rgba(255,253,247,.8)` 一类的蒙层在深色下会发灰，统一抽成 `--hd-veil` / `--hd-veil-soft` / `--hd-hover`，深色值改为深咖啡与 6% 白。

## 15.4 字体与降级

| 用途 | 字体 | 说明 |
| --- | --- | --- |
| 标题 / 分节号 | HanziPen SC（翩翩体） | 手写感最强 |
| 正文 | Hannotate SC（手札体） | 比娃娃体清晰，12px 以下仍偏软 |
| 编号 / 计数 | Bradley Hand | 数字与 `IG-032` 这类编号最好认 |
| 注释小字 | 系统无衬线（PingFang SC） | 清晰优先，避免小字发糊 |
| 长段提示词 | Wawati SC（娃娃体） | 大段文本可读性更好 |

全部为 macOS 自带；其它平台按 `sans-serif` 回落——版式与配色不变，手写感减弱。文档里已写明这一点。

## 15.7 待办与取舍

- 目前**不做「手绘 / 朴素」开关**：默认即手绘。若要加，只需在设置里存一个布尔并把 `<link>` 的注入改成条件式。
- 卡片旋转幅度保持在 0.35–0.9°，克制优先；想更像手账可整体调大。
- 深色下模板示例图本身是浅色位图，与深色纸的反差较大，属预期（素材图来自上游，不做自动反色）。
